title: Uniswap V4 Hooks

---

LFG.RICH 基于 Uniswap V4 Hook 架构构建。Hook 不只是辅助合约，而是官方代币协议逻辑的核心：联合曲线、地板价会计、手续费路由、推荐奖励分配、抵押借贷规则，全部由 Hook 执行。

用户看到的交易流程很简单，但链上路径是固定的：

```txt
用户钱包
  -> Swap Router
  -> Pool Manager unlock(...)
  -> Pool Manager swap(...)
  -> Uniswap V4 Hook beforeSwap(...)
  -> 自定义曲线、地板价、手续费和会计逻辑
  -> Pool Manager settle / take 结算
```

## 主要合约

| 合约 | 职责 |
| --- | --- |
| Factory | 创建官方 LFG.RICH 代币，并将它们注册到 hook。 |
| Uniswap V4 Hook | 处理定价、地板价、储备、手续费、抵押、借贷和 hook 回调。 |
| Swap Router | 为用户和集成方提供简单的买入和卖出函数。 |
| Token | 由 Factory 创建的 ERC20 兼容代币合约。 |
| Pool Manager | hook 和 router 流程使用的 Uniswap V4 Pool Manager。 |

## PoolKey 和 poolId

每个官方代币都有自己的 Uniswap V4 `PoolKey` 和自己的 `poolId`。

```solidity
struct PoolKey {
    address currency0;   // 原生 BNB，用 address(0) 表示
    address currency1;   // 代币地址
    uint24 fee;          // 3000
    int24 tickSpacing;   // 60
    address hooks;       // Uniswap V4 Hook
}
```

集成时最重要的规则是：**不要猜测使用哪个池**。必须为当前代币解析 `poolId` 和 `PoolKey`。

```txt
poolId = token.pool_id || token.poolId || hook.tokenToPoolId(tokenAddress)
key    = factory.getPoolKey(tokenAddress)
```

网站代码会把代币的 `poolId` 视为交易上下文的一部分。估算使用 `poolId`，买卖执行使用 `PoolKey`。

## 为什么 Hook 很重要

Hook 让代币不再像普通的、由创建者管理 LP 的代币。创建者不会拿到可移除的 LP token。交易者也不会与随意的第三方池交互。官方交易会进入协议合约，由 Hook 对所有人执行同一套定价、地板价、手续费、推荐和抵押规则。

协议执行路径保持一致：

- 买入和卖出使用官方 Swap Router；
- 定价由 Hook 计算；
- 代币铸造和销毁由 Hook 控制；
- 抵押借贷使用同一个基于 `poolId` 的状态；
- 地板价更新与该代币自身协议状态绑定；
- 推荐奖励由链上邀请绑定决定。

## 重要集成规则

<Warning>
旧 V3 示例不能直接用于 V5。V5 的估算函数包含用户地址，创建代币使用 `devBuyEth`，买卖必须使用该代币正确的 `PoolKey` 路由。
</Warning>

V5 应使用以下模式：

```txt
1. 加载代币数据。
2. 解析 poolId。
3. 解析 PoolKey。
4. 使用 Hook + poolId + 用户地址估算。
5. 使用 Swap Router + PoolKey 执行买入/卖出。
6. 使用 Hook + poolId 执行 borrow、borrowMore 和 repay。
```
