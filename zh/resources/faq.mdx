## 入门

### 什么是 LFG.RICH？

LFG.RICH 是一个基于 BNB Smart Chain 的代币发射平台，核心架构围绕 Uniswap V4 Hook 构建。通过平台创建的代币使用协议管理的联合曲线交易、地板价保护、抵押借贷和推荐奖励机制。

它不是依赖普通外部流动性池的发射模式。官方 LFG.RICH 流程会通过协议合约处理代币创建、交易、定价、地板价、手续费和借贷。

### 如何创建代币？

打开应用，连接钱包，然后进入 **Create Token** 页面。

你需要填写：

- 代币名称
- 代币符号
- 代币 Logo
- 可选描述
- 可选网站
- 可选 X/Twitter 链接
- 可选 Telegram 链接
- 可选 QQ 群
- 可选初始买入金额

V5 的重要变化是：创建者已经**不能选择代币交易手续费**。表单可以允许填写可选初始买入金额，但手续费率不是由创建者选择的。

确认交易后，Factory 会创建 Token，将它注册到 Uniswap V4 Hook，初始化 Pool Manager 流程，并在 `devBuyEth` 大于 0 时执行可选初始买入。

### 创建代币需要什么？

你需要：

- 兼容的钱包
- 用于 Gas 的 BNB
- 如果当前设置了创建费用，需要足够的 BNB 支付创建费用
- 如果你想做初始买入，需要额外准备对应的 BNB

创建交易的 `value` 基于创建费用加上可选初始买入金额。如果当前创建费用是 `0`，那么只需要 Gas 和可选初始买入金额。

### 创建者可以选择代币交易手续费吗？

不可以。这个功能在 V5 已经移除。

在 V5 中，买入/卖出交易手续费由协议固定：

| 手续费 | 比例 | 说明 |
|---|---:|---|
| 买卖总手续费 | 1.25% | 由 Hook 在交易时执行 |
| 平台部分 | 0.25% | 协议/平台部分 |
| 推荐部分 | 1.00% | 符合条件时给交易者的 initial inviter，否则进入平台侧 |

创建者不应该在 V5 创建代币表单中寻找手续费选择项。创建流程里唯一可选的金额是初始买入。

### 代币创建后会发生什么？

创建后：

<Steps>
  <Step title="代币合约部署到链上">
    代币会作为 V5 创建流程的一部分部署。
  </Step>
  <Step title="Factory 注册该代币">
    Factory 会把该代币记录为官方 LFG.RICH 代币。
  </Step>
  <Step title="Hook 按 poolId 保存代币状态">
    V5 协议状态按 `poolId` 保存。
  </Step>
  <Step title="Pool Manager 流程完成初始化">
    代币会连接到 Uniswap V4 Pool Manager 和 Hook 流程。
  </Step>
  <Step title="代币可以通过官方 Swap Router 交易">
    买入和卖出使用官方 V5 路由路径。
  </Step>
  <Step title="代币页面可以展示协议数据">
    价格、地板价、供应量、成交量、交易和借贷数据会提供给 App 和集成使用。
  </Step>
</Steps>

代币一开始没有流通供应量。只有当用户通过联合曲线买入时，代币才会被铸造。如果创建者执行了初始买入，那么该买入会在发射时为创建者铸造第一批代币余额。

## 交易与市场

### 买入是如何工作的？

用户通过 Swap Router 使用 BNB 买入。Router 会将操作送入 Uniswap V4 Pool Manager 流程，然后 Hook 使用该代币的 `poolId` 计算实际输出的代币数量。

买入流程是：

```text
用户 -> Swap Router -> Pool Manager -> Uniswap V4 Hook -> 代币铸造给买家
```

应用和集成方必须使用正确的 `poolId`。在 V5 中，Hook 状态按 `poolId` 保存，所以在估算或执行交易前，应从应用 API、代币数据或 Hook/Factory 合约解析正确的 `poolId`。

### 卖出是如何工作的？

用户通过 Swap Router 卖出代币。卖出前，用户必须先授权 Swap Router 使用该代币。

Hook 会计算可获得的 BNB，销毁卖出的代币，应用 V5 交易手续费，并确保有效价格不会跌破协议地板价。

卖出流程是：

```text
用户授权 Token -> Swap Router -> Pool Manager -> Uniswap V4 Hook -> BNB 支付给卖家
```

### 什么是地板价？

地板价是 Hook 使用的协议强制最低有效价格。在 V5 中，默认地板价规则非常重要也很直接：

```text
地板价 = ATH 的 50%
```

`ATH` 指 Hook 为该代币记录的历史最高价。当代币达到新的 ATH 时，地板价可以上升。地板价一旦上升，就不会下降。

### 代币价格会归零吗？

一旦地板价建立后，协议有效价格不能被压到该代币地板价以下。地板价由 Hook 强制执行，卖出也通过 Hook/Router 流程处理，而不是通过普通外部流动性池处理。

非常早期的代币可能仍在建立最初的有效价格和地板价状态。有了交易历史和 ATH 数据后，地板价机制会防止协议有效价格跌破记录的地板价。

### 为什么集成方必须检查 `poolId`？

因为 V5 的重要操作是按 `poolId` 路由的，而不只是按代币地址路由。

代币地址识别 ERC-20 代币，但 Hook 的状态保存在池标识符下面。在报价、买入、卖出、借贷、Borrow More 或还款之前，集成方应解析正确的 `poolId` 并始终使用它。

常用 V5 读取包括：

```text
hook.tokenToPoolId(tokenAddress)
hook.tokenStates(poolId)
hook.getEffectivePrice(poolId)
hook.estimateBuy(poolId, ethIn, buyer)
hook.estimateSell(poolId, tokenAmount, seller)
```

### 是否有普通流动性提供者？

没有。LFG.RICH V5 模型由协议管理。交易通过官方 Hook 和 Router 流程处理。传统外部 LP 添加并不是普通用户流程的一部分，并且会被 Hook 拒绝。

## 借贷

### 借贷是如何工作的？

借贷允许代币持有人锁定代币作为抵押品，并按代币地板价值借出 BNB。

核心逻辑是：

```text
锁定代币抵押品 -> 地板价值 -> 可借 BNB
```

可借金额基于地板价，而不是短期市场尖峰价格。用户先授权 Hook 转移代币，然后通过应用或直接通过 Hook 执行借贷流程。

### 会有清算吗？

不会。LFG.RICH 借贷没有清算机制。

当你有债务时，你的抵押品会锁定在 Hook 中。它不会被清算人卖出，也没有强制还款期限。要解锁抵押品，需要偿还借出的 BNB。

### 借贷手续费是多少？

借贷有一次性 V5 借贷手续费：

| 手续费 | 比例 | 说明 |
|---|---:|---|
| 借贷总手续费 | 3.00% | 按借出价值计算 |
| 平台部分 | 1.00% | 协议/平台部分 |
| Parent 奖励部分 | 2.00% | 符合条件时给借款人的直接 parent，否则进入平台侧 |

没有持续利息。手续费会在 borrow 或 borrow-more 操作发生时应用。

### 什么是 Borrow More？

如果你已经用抵押品借过 BNB，之后代币地板价上升，你锁定的抵押品可能支持更多可借价值。**Borrow More** 可以在不增加抵押品的情况下借出新增的可用金额。

如果没有新增可借价值，Borrow More 不可用。

### 可以部分还款吗？

可以。部分还款会按比例解锁被锁定的抵押品。

例如，如果用户偿还剩余债务的一半，就会释放对应比例的锁定代币。如果用户完全偿还债务，剩余抵押品会全部解锁。

### 如果我多还了怎么办？

Hook 只会使用减少或清偿债务所需的金额。多余部分会通过合约流程退回。

## 推荐与奖励

### 使用 LFG.RICH 必须有推荐人吗？

不需要。用户可以在没有绑定推荐人的情况下创建代币、买入、卖出、借贷和还款。

推荐绑定对用户是可选的，但它会影响奖励。如果用户未绑定且没有符合条件的推荐奖励接收方，协议手续费中的推荐部分会进入平台侧。

### 推荐绑定如何工作？

用户可以通过推荐流程绑定邀请人。绑定是一次性的，并且永久生效。

邀请人必须符合条件。推荐树中通常符合条件的邀请人包括：

- 白名单根地址；或
- 已经绑定在合格推荐树下的用户。

用户绑定后，会拥有一个直接 **parent** 和一个 **initial inviter**。

### 什么是白名单地址？

白名单地址是平台批准的推荐系统根地址。

白名单地址可以开启推荐分支。普通用户之后通过绑定符合条件的邀请人加入这些分支。

这套白名单/根节点逻辑非常重要，因为它可以防止任意伪造根节点，并让推荐奖励与已批准的推荐树关联。

### parent 和 initial inviter 有什么区别？

**parent** 是用户上一级的直接邀请人。

**initial inviter** 是该推荐分支的根邀请人，通常是用户推荐树顶部的白名单根地址。

V5 对两者的使用不同：

| 操作 | 奖励接收方 | 奖励 |
|---|---|---:|
| 买入/卖出 | Initial inviter | 交易金额的 1.00% |
| Borrow/Borrow More | 直接 parent | 借出价值的 2.00% |

这个区别是有意设计的。交易奖励跟随 initial inviter，而借贷奖励跟随直接 parent。

### 推荐人从交易中赚多少？

买入和卖出交易的推荐奖励是**交易金额的 1.00%**。

这是 V5 固定 1.25% 买卖总手续费中的 inviter fee 部分。如果交易者没有符合条件的 initial inviter，或推荐奖励被关闭，该部分会进入平台侧。

### parent 从借贷中赚多少？

Borrow 和 Borrow More 的 parent 奖励是**借出价值的 2.00%**。

这不是 3% 手续费里面的 2%。它是借贷手续费结构中的 parent 部分，按借出价值计算。如果借款人没有符合条件的 parent，或推荐奖励被关闭，该部分会进入平台侧。

### 之后可以更换推荐人吗？

不可以。推荐绑定是永久的。用户绑定前应仔细检查邀请人。

## 技术与安全

### 我的钱包安全吗？

LFG.RICH 不会保存你的私钥或助记词。交易由你的钱包签名。请只通过官方链接连接钱包，认真检查每一个钱包弹窗，并且不要把助记词告诉任何人。

### LFG.RICH 使用哪条区块链？

当前 LFG.RICH 文档和 V5 协议示例重点面向 BNB Smart Chain。

创建代币或发送交易前，请始终检查钱包中选择的链是否正确。

### 创建后可以修改代币吗？

链上代币属性，例如代币合约、名称和符号，在创建后是固定的。请把创建时提交的信息视为最终信息，并在确认前仔细检查。

### 合约可以升级吗？

V5 核心经济流程由已部署合约执行。用户和集成方应以文档中发布的官方合约地址和 ABI 为准。

根据部署合约的不同，可能存在一些管理设置，例如创建费用配置、推荐合约设置或奖励开关。核心交易、地板价和借贷行为应根据合约参考理解，而不是依赖前端假设。

### 如果前端不可用怎么办？

代币和协议状态都在链上。高级用户和集成方仍然可以使用开发者文档中的官方合约地址、ABI、`poolId`、Hook 读取、Router 函数和借贷函数直接与合约交互。
